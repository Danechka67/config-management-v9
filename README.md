# Эмулятор UNIX-подобной оболочки — вариант 9

Практическая работа № 1 по дисциплине «Конфигурационное управление».
Python 3.10+ и Tkinter. Сторонние Python-пакеты не нужны, сборка не нужна.
GUI показывает историю ввода и вывода, приглашение содержит текущий путь,
заголовок окна содержит имя VFS (имя CSV без расширения).

## Быстрый запуск

Распакуйте проект, откройте терминал **в папке variant9**.
Windows: `python -m src.main` или `run.bat`.
Linux/macOS: `python3 -m src.main` или `sh run.sh`.
При установке Python в Windows включите компонент Tcl/Tk.
В Linux, если Tkinter отсутствует, установите пакет `python3-tk`
средствами своего дистрибутива. GUI требует рабочего графического сеанса.
Проверка доступности Tkinter: `python -m tkinter`.

Демо всех команд (в конце окно закроется по `exit`):

```sh
python -m src.main --vfs examples/deep.csv --startup examples/all.txt
```

Для демо с последующим ручным вводом используйте `examples/commands.txt`
либо `examples/removal.txt`: в них нет завершающего `exit`.
Начните с `ls`, затем `cd /docs/course/week1` и `tail -n 2 notes.txt`.
Все операции с виртуальными файлами происходят в памяти.
Удаления исчезают после перезапуска, исходный CSV не изменяется.

## Настройки запуска

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `--vfs ПУТЬ` | `examples/deep.csv` | CSV-источник VFS |
| `--startup ПУТЬ` | нет | UTF-8 файл с командами |
| `--help` | — | Справка по аргументам |

Относительные пути к CSV и скрипту считаются от рабочей папки ОС.
Скрипты `run.sh` и `run.bat` переходят в папку проекта перед запуском.
Настройки печатаются в графическом журнале при запуске.
Команды скрипта исполняются последовательно и показываются с выводом.
После ошибочной строки выполнение продолжается. Пустые строки допустимы.
`exit` завершает сеанс, поэтому последующие строки не выполняются.
Недоступный скрипт выводит ошибку, ручной ввод остаётся доступен.
При ошибке загрузки VFS ручной ввод отключается: исправьте CSV и перезапустите.

## Команды

| Синтаксис | Поведение |
|---|---|
| `ls [путь]` | Содержимое каталога или имя файла; без пути — текущий каталог |
| `cd [путь]` | Сменить каталог; без аргумента — корень `/` |
| `date [+формат]` | Локальное время ОС; формат Python strftime, например `+%Y-%m-%d` |
| `tail [-n N] файл` | Последние N строк UTF-8 файла; по умолчанию 10, N ≥ 0 |
| `rm [-r] [-f] [--] путь...` | Удалить один или несколько узлов в памяти |
| `exit` | Закрыть окно и завершить сеанс |

`rm -r` или `rm -R` удаляет каталоги с потомками.
`rm -f` игнорирует отсутствующий путь; комбинация `-rf` поддерживается.
`--` завершает разбор флагов и позволяет удалить имя, начинающееся с `-`.
Защищены корень, текущий каталог и его предки. Если хотя бы один путь
неверен, весь список удаления отклоняется до изменения VFS.
`ls` сортирует имена и добавляет `/` к именам каталогов.
Пустой каталог и пустой файл дают пустой вывод.
`tail -n 0` выводит ничего, большое N выводит файл целиком.
Нетекстовые данные сохраняются в VFS, но tail требует UTF-8.

Парсер намеренно простой: `str.split()`, как требует задание.
Кавычки, пути с пробелами, подстановка переменных, конвейеры,
перенаправления и полная семантика UNIX-команд не реализованы.
Поддерживаются абсолютные/относительные POSIX-пути, `.`, `..`, повторные `/`.
Выход через `..` выше корня остаётся в корне.

## Формат CSV и вложенность

UTF-8, точные колонки `path,type,content`. `path` — канонический абсолютный
POSIX-путь, `type` — `dir` или `file`, `content` — base64 байтов файла.
Для каталогов content пустой. Родительские каталоги должны быть указаны,
но порядок строк произвольный. Корень `/` создаётся автоматически.

```csv
path,type,content
/,dir,
/docs,dir,
/docs/hello.txt,file,SGVsbG8K
```

Последняя запись содержит `Hello` и перевод строки.
Получить base64: `python -c "import base64; print(base64.b64encode(b'Hello\n').decode())"`.
Двоичные файлы тоже представлены текстовой base64-строкой внутри CSV,
отдельных двоичных файлов в репозитории нет.
Проверяются заголовок, количество полей, типы, пути, повторы,
содержимое каталогов, base64 и существование родительских каталогов.

| Пример | Содержимое |
|---|---|
| `examples/minimal.csv` | Только корень |
| `examples/files.csv` | Несколько файлов, включая пустой и двоичный |
| `examples/deep.csv` | Три уровня каталогов, русский текст и лог из 15 строк |

## Структура и назначение модулей

| Файл | Назначение |
|---|---|
| `src/main.py` | Настройки, загрузка VFS, запуск окна и стартового скрипта |
| `src/config.py` | Разбор параметров командной строки |
| `src/gui.py` | Журнал терминала и обработчик Enter |
| `src/shell.py` | Парсер, состояние сеанса и команды |
| `src/vfs.py` | Node, CSV-загрузчик, нормализация путей, поиск узлов |
| `src/removal.py` | Разбор rm, проверка целей и удаление в памяти |
| `src/startup.py` | Чтение и последовательное исполнение скрипта |
| `tests/` | Автоматические проверки логики без открытия GUI |
| `scripts/` | Сценарии запуска GUI для Windows и Linux/macOS |

У функций и методов есть docstring с описанием назначения.
При ошибках команды возвращают сообщение с префиксом «Ошибка».
GUI не вызывает команды ОС и не использует shell/subprocess для ввода.

## Проверка

```sh
python -m unittest discover -s tests -v
```

На Linux/macOS при необходимости замените `python` на `python3`.
Тесты проверяют команды, ошибки, base64, вложенность, время,
продолжение скрипта после ошибки и сохранность CSV при удалении.
Ручные сценарии: `scripts/check_config.bat`, `scripts/check_vfs.bat`
или соответствующие `.sh`. Каждый открывает несколько окон последовательно;
закройте текущее окно для перехода к следующему вызову.
Скрипт vfs.txt намеренно содержит отсутствующие пути для проверки ошибок.

Проверка GUI перед защитой: заголовок содержит имя VFS, Enter выполняет
команды, журнал показывает ввод/вывод, приглашение меняется после cd,
exit закрывает окно. Проверьте на своей машине с графическим сеансом.

## Пять этапов и GitHub

В поставляемой папке сохранён каталог `.git` с пятью коммитами.
Это история подготовки проекта; коммиты созданы автоматически
автором Project Generator, без подстановки имени студента.
Последовательность соответствует этапам задания:

1. GUI REPL и заглушки ls/cd, exit.
2. Параметры --vfs/--startup и исполнение скрипта.
3. Загрузка CSV VFS в память и примеры вложенности.
4. Реальные ls/cd, date и tail.
5. rm, полный демонстрационный скрипт и документация.

Посмотреть: `git log --oneline`. Проверить отдельный этап можно без смены
основного проекта: `git worktree add ../stage1 ХЕШ_ПЕРВОГО_КОММИТА`.
В этапе 1 и 2 ls/cd — заглушки; в этапе 3 VFS уже загружается,
реальные команды появляются на этапе 4. Этап 1 не требует CSV-файла.

Создайте на GitHub **публичный пустой репозиторий** без README/gitignore.
Из папки variant9 выполните, заменив адрес своим:

```sh
git remote add origin https://github.com/USERNAME/config-management-v9.git
git push -u origin main
```

Если GitHub запросит вход, авторизуйтесь своим обычным способом.
Архив проекта нужен только для передачи: не добавляйте ZIP в репозиторий.
Загрузка файлов через веб-интерфейс не переносит готовую историю коммитов;
для неё используйте git push.
Настройте автора **будущих собственных изменений**:

```sh
git config user.name "Ваше имя"
git config user.email "Ваш email GitHub"
```

До защиты разберите модули и выполните демонстрацию самостоятельно:
защита каждого этапа по методичке проходит очно.
